# Инструкции для агентов

## Назначение проекта

Проект - автономное мобильное веб-приложение "Эхолот" для сохранения рыболовных мест, промеров глубины и параметров катушки. Интерфейс и пользовательские сообщения написаны на русском языке. Приложение работает без сервера и хранит данные локально в браузере.

## Структура

Основной UI остаётся в `index.html`, но приложение больше не строго однофайловое:

- `index.html` содержит тему, разметку, хранение, навигацию, экраны и обработчики.
- `app-core.js` содержит тестируемые чистые контракты: миграцию схемы, валидацию импорта, координаты и геопроекцию.
- `vendor/leaflet/` - локально вендоренный Leaflet 1.9.4; CDN не используется.
- `lakes/` - готовые пакеты водоёмов: реестр, манифесты, XYZ PNG и precache-список.
- `manifest.webmanifest`, `sw.js`, `icons/` обеспечивают установку PWA и офлайн-кэш.
- `tools/lake-package.mjs` готовит пакеты (`build`) и перевыпускает версию оболочки без пакетов (`restamp`).
- `tests/` проверяет модель, геопроекцию и пайплайн встроенным `node:test`.

Не добавляйте сборщик, фреймворк, пакетный менеджер или новые внешние зависимости без прямого требования. Leaflet - согласованное исключение, вендоренное локально.

## Запуск

Сборка и установка зависимостей не нужны. Запускайте локальный HTTP-сервер из корня проекта:

```bash
python3 -m http.server 8000
```

Открывайте `http://localhost:8000/`. Используйте HTTP-сервер, а не `file://`: так поведение браузерных API ближе к реальной эксплуатации.

## Архитектура приложения

- `DB` - единое изменяемое состояние приложения: `waterbodies[] -> places[] -> lines[] -> measures[]`, катушка, пресеты и настройки графиков.
- Основное хранилище - `localStorage` с ключом `fishmap.db.v1`; при его отсутствии используется `window.storage`.
- `load()` загружает данные, `AppCore.normalizeDatabase()` мигрирует старый плоский `places[]` в водоём «Без привязки», `save()` сохраняет состояние с задержкой.
- `route` задает текущий экран. `go()` меняет маршрут, `render()` создаёт разметку и подключает обработчики.
- Функции `view...()` должны только формировать HTML. Соответствующие `after...()` подключают поведение после вставки разметки.
- `viewCleanup` освобождает Canvas-обработчики и экземпляр Leaflet текущего экрана перед повторным рендерингом.
- Профиль и схематичный вид сверху рисуются через Canvas API. Геореференсная карта водоёма рисуется Leaflet из локального пакета.
- Обороты переводятся в метры снастью луча: `line.spool` - снимок `{ name, size, core, width, ratio, lineD, lineL }`, при `null` берётся `activeSpool()`. Все пересчёты идут через `spoolForLine()` и `lineDistance()`, глобальную катушку читает только калькулятор ([ADR-0006](docs/adr/0006-snast-na-luche.md)).
- Замеры одного луча с точно совпадающими оборотами образуют группу. Группировка - только представление: `AppCore.groupMeasures()` даёт по одной точке на уникальные обороты (счёт - среднее с шагом 0.5; дно и метка - большинство среди заполненных, ничья за более новым замером). На неё опираются профиль, вид сверху, sparkline и геореференсная карта. Хранилище меняет лишь явное «Объединить» через `AppCore.mergeGroup()` ([ADR-0001](docs/adr/0001-gruppirovka-i-usrednenie-zamerov.md)).
- Экспорт и импорт используют JSON. `AppCore.validImport()` является границей доверия для загружаемых файлов.
- Сборщик публикует immutable `lakes/<slug>/<release>`, `lakes/registry/<release>.json` и `lakes/precache/<release>.json`, затем переключает `lakes/index.json` и встраивает `generatedAt` в `SW_VERSION` файла `sw.js`. Worker проверяет опубликованную версию, кэширует свой versioned registry под стабильным URL и ждёт закрытия вкладок старой версии; runtime-запросы обслуживаются только из cache текущей версии.
- Пункт меню «Установить на телефон» перехватывает `beforeinstallprompt` и вызывает системный диалог; когда события нет (iOS, уже установлено), показывается инструкция по ручному добавлению на домашний экран. В standalone-режиме и после `appinstalled` пункт скрыт.

## Правила изменений

- Сохраняйте мобильный подход, ширину основного контента до 600 px, safe-area отступы и поддержку `prefers-reduced-motion`.
- Используйте существующие CSS-переменные темы и классы компонентов. Не создавайте вторую дизайн-систему.
- Пользовательский текст пишите на русском языке. Имена JavaScript-символов и технические идентификаторы - на английском.
- Любые пользовательские значения, вставляемые в HTML-строки, пропускайте через `esc()`. Для простого текста предпочитайте `textContent`.
- После изменения `DB` вызывайте `save()`. Если изменение должно быть видно сразу, затем вызывайте `render()` или переходите через `go()`.
- При изменении схемы данных обновляйте одновременно значения по умолчанию, `normalizeDB()`, импорт, экспорт и все места чтения данных. Старые сохранения должны продолжать загружаться.
- Не ослабляйте `validImport()`. Новые импортируемые поля должны проверяться до присваивания в `DB`.
- Не оставляйте глобальные обработчики и анимационные кадры после ухода с экрана. Освобождайте их через `viewCleanup`.
- Не встраивайте непроверенные данные в селекторы, атрибуты, SVG или Canvas-подписи.
- Не меняйте формулы катушки без проверки прямого и обратного преобразований `metersToTurns()` и `turnsToMeters()` на граничных значениях.
- Сохраняйте автономную работу: новые основные сценарии не должны требовать сети.
- После изменения `index.html`, `app-core.js`, `sw.js`, `manifest.webmanifest`, `icons/` или `vendor/` выполняйте `node tools/lake-package.mjs restamp` до публикации. Без нового `SW_VERSION` установленные клиенты продолжат работать со старой копией из cache.

## Проверка

Автоматические проверки есть для чистой модели, пайплайна и service worker:

```bash
node --test tests/app-core.test.js tests/lake-package.test.mjs tests/sw.test.mjs
```

После UI-изменений дополнительно выполняйте целевой smoke-тест в браузере.

Минимальная проверка общих изменений:

1. Открыть приложение без ошибок в консоли.
2. Создать водоём, внутри него место и луч, добавить не менее двух промеров.
3. Открыть профиль, схематичную карту дна и геореференсную карту водоёма.
4. Убедиться, что локальный XYZ-тайл, граница, лучи и точки замеров отображаются.
5. Перезагрузить страницу и убедиться, что данные сохранились.
6. Остановить HTTP-сервер, перезагрузить управляемую service worker вкладку и проверить офлайн-открытие карты.
7. Экспортировать JSON, удалить или изменить данные, затем импортировать файл обратно.
8. Проверить узкий мобильный viewport и обычный настольный viewport.

Для изменений хранения или схемы данных дополнительно проверяйте пустое хранилище, legacy `places[]`, новую вложенную схему и некорректный импорт.

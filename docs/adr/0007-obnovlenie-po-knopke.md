# Обновление применяется по кнопке, а не по закрытию вкладок

Новый service worker по-прежнему не вызывает `skipWaiting()` при установке, но получает сообщение `{ type:"skip-waiting" }` от страницы. Приложение показывает кнопку «Обновить приложение», когда worker дошёл до состояния `installed` при уже работающем контроллере; по нажатию worker выходит из ожидания, и все страницы под его управлением перезагружаются по `controllerchange`.

Причина: прежний порядок требовал закрыть все вкладки и окна старой версии. На телефоне это невыполнимо вслепую - установленная PWA висит в переключателе приложений, а сайт часто остаётся открытым в фоновой вкладке браузера. Опубликованный пакет водоёма при этом не появлялся сколько угодно долго, хотя `lakes/index.json`, precache и cache новой версии уже были на устройстве.

Инвариант ADR-0003 сохраняется: набор ресурсов не подменяется посреди сессии молча. Смена версии происходит только по явному действию пользователя и сразу же сопровождается перезагрузкой каждой управляемой страницы, поэтому старая разметка никогда не работает с новым cache.

## Последствия

- `sw.js` получает обработчик `message`; `skipWaiting()` вызывается только для типа `skip-waiting`. Любое другое сообщение игнорируется.
- Страница перезагружается на `controllerchange` с однократной защитой от повторного вызова. Несохранённого состояния экрана это не рушит: `DB` пишется в `localStorage` через `save()`.
- Проверка обновления запускается при регистрации и при каждом возврате вкладки в видимое состояние. Установленная PWA, которую не перезапускают неделями, всё равно узнаёт о новой версии.
- Без нажатия поведение прежнее: новая версия ждёт, приложение работает на старом cache. Пользователь, которому не нужно обновление посреди рыбалки, ничего не теряет.

# Пакет реки собирается по району работ, а не по всему руслу

Тип `river` теперь строится тем же сборщиком, что озеро и водохранилище. Геометрия берётся из водной поверхности OSM (`natural=water`), а район работ задаётся прямоугольником `--clip minLon,minLat,maxLon,maxLat`: граница обрезается по нему, и `bbox` пакета получается из уже обрезанной геометрии.

Причина: у реки нет естественной замкнутой границы нужного масштаба. Отношение водной поверхности покрывает десятки километров русла: у Припяти под Пинском это `bbox` примерно 8 x 17 км и около 9500 тайлов на `z18`. Рыбалка привязана к одному участку, а не ко всему руслу, поэтому пакет должен ограничиваться районом, который пользователь реально обходит.

Обрезка идёт алгоритмом Сазерленда-Ходжмана по каждому кольцу отдельно: внешнее кольцо остаётся одним контуром, острова сохраняются дырками, кольца целиком за пределами прямоугольника отбрасываются. Пустое пересечение - ошибка сборки, а не пустой пакет.

## Последствия

- `--clip` работает для любого типа, не только для реки: тем же способом отрезается лишнее у большого водохранилища.
- В манифест пишется обрезанная граница, поэтому приложение рисует ровно ту область, для которой скачаны тайлы.
- Прямоугольник обрезки - часть входных данных сборки. Чтобы пересобрать тот же пакет, нужно передать те же `--clip` и `--generated-at`.
- Скачиваются все тайлы `bbox`, включая берега за пределами воды. Для узкой излучины это переплата по количеству запросов; фильтрация тайлов по полигону не вводится, пока пакеты остаются в сотнях тайлов.
- Ограничение приложения снято: водоём типа «Река» теперь может ссылаться на `packageSlug`, а `validLakeManifest()` принимает `type: "river"`. Без пакета река ведёт себя как раньше.
